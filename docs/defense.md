# Краткая подготовка к защите

Перед защитой откройте каждую страницу и попробуйте заполнить форму самостоятельно. Объяснения ниже нужно связать с конкретными строками своего HTML и CSS.

1. **Зачем нужен `label`?** Он задаёт понятное имя поля для экранного диктора. Связь `for="age"` и `id="age"` позволяет нажать на подпись и поставить фокус в поле. Placeholder не заменяет подпись: он исчезает после ввода.
2. **Чем `name` отличается от `id`?** `id` связывает поле с подписью и CSS. `name` — имя ключа при отправке формы. Поле без `name` не попадёт в данные формы.
3. **Как работает `required`?** Браузер запрещает обычную отправку формы, пока обязательное поле пустое. У `select` пункт «Choose…» имеет пустое значение. У группы radio одинаковый `name`, поэтому можно выбрать только один вариант.
4. **Почему типы полей разные?** `email` проверяет синтаксис адреса, `url` требует полный URL, `number` проверяет число, `date` и `time` дают встроенные элементы выбора. Тип `email` не проверяет существование почты и не ограничивает адрес доменом университета: такого требования в таблице нет.
5. **Как задать диапазон и шаг?** Возраст: `min="16" max="30" step="1"`. Время: `min="09:00" max="18:00" step="1800"`; шаг времени задан в секундах, 1800 секунд = 30 минут. Взнос: `min="0" max="5000" step="500"`.
6. **Как задать длину?** `minlength` задаёт минимум, `maxlength` ограничивает ввод сверху. Для обязательного текста нужен ещё `required`, иначе пустое необязательное поле допустимо. Слишком длинный текст обычно нельзя полностью ввести: браузер остановит ввод на `maxlength`.
7. **Почему ошибки скрыты при открытии?** CSS использует `:user-invalid`, который появляется после взаимодействия пользователя с полем. Обычный `:invalid` сразу отмечал бы пустые обязательные поля. `.invalid-feedback` — текст сообщения; браузер также выдаёт своё сообщение при попытке отправки.
8. **Как Bootstrap помогает мобильной версии?** `.row`, `.col-12` и колонки с breakpoint задают перенос полей. На узком экране поля стоят друг под другом. Классы порядка позволяют поменять визуальное положение кнопок без перестановки HTML.
9. **Что делает Clear?** Кнопка с `type="reset"` возвращает исходные значения полей. Поэтому исходные текстовые значения не заданы: они очищаются. Radio и checkbox возвращаются к состоянию, указанному в HTML.
10. **Как проверить клавиатуру?** Tab и Shift+Tab переходят между элементами, стрелки выбирают radio, Space переключает checkbox, Enter отправляет форму. Фокус должен оставаться видимым; положительные `tabindex` здесь не нужны.
11. **Что происходит после отправки?** Это учебные формы без сервера хранения данных. Нативная валидация выполняется в браузере. Для реального сервиса необходима повторная проверка на сервере, потому что клиентский HTML можно изменить.
12. **Что доказывает валидатор?** W3C проверяет корректность разметки. Он не доказывает визуальное сходство, удобство или полную доступность: эти свойства дополнительно проверяют в браузере.

Для демонстрации в Task 2: введите `A`, затем `Li`; возраст `15`, затем `16`; время `10:15`, затем `10:30`; взнос `1250`, затем `1500`. Снимите флажок согласия и попробуйте отправить форму. Объясните, какое HTML-ограничение останавливает каждый неверный вариант.

Перед сдачей проверьте имя, группу и настоящий URL репозитория в отчёте. На защите потребуется самостоятельно объяснить и изменить код.
